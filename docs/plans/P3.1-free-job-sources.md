## 1. Goal

Every search run pulls from as many **free** sources as possible, all with the same rules: catalog, Free-tools-only mode, user on/off switches, keys, health, dedup, scoring and seen-skip. No captcha or bot-wall bypass (§12).

**Acceptance criteria**
1. With no API keys at all, a search for "Python Developer, Bangalore + Remote" returns jobs from at least LinkedIn, Indeed and the keyless remote feeds.
2. When a user adds a free Adzuna, Jooble or Careerjet key under `/keys`, those sources run for that user. Without a key they are skipped, with the reason shown (existing `skipped_sources`).
3. Five new company-ATS platforms work in `/company-ats`: Ashby, Recruitee, Workable, Personio and Breezy.
4. The same job from Adzuna and LinkedIn appears once, and the LinkedIn copy is kept (existing rule).
5. A source that fails N times in a row is paused automatically, then retried after a cooldown.
6. Remote feeds are downloaded at most once per TTL, however many keyword tasks run in parallel.
7. All adapters have offline tests using recorded fixtures, so CI makes no network calls.

## 3. Design

### 3.1 Adapter package (blueprint §16: `app/providers/` holds job-source adapters)
```
app/providers/job_sources/
  base.py        # JobSource protocol, SourceQuery, normalize helpers, http client w/ timeout + UA
  jobspy.py      # linkedin, indeed, glassdoor, google_jobs (wraps existing _run_jobspy)
  adzuna.py  jooble.py  careerjet.py
  feeds.py       # remoteok, remotive, himalayas, jobicy, arbeitnow, themuse, wwr
  registry.py    # key -> adapter; display name <-> key mapping
```
- `SourceQuery(keyword, location, country="in", max_age_hours, results_wanted, remote_ok: bool)`.
- Each adapter returns the **existing job dict shape** (`source, title, company, location, url, description, posted`) plus optional `remote`, `salary`, `external_id` and `description_partial`. Nothing downstream changes: `_validate_jobs`, `job_dedupe`, `job_store.upsert_copy` and the scorer all keep working.
- `job_sources.scrape_all` keeps its signature. Internally it loops over `registry` adapters instead of calling JobSpy directly. The legacy body still works.

### 3.2 Three source kinds
1. **JobSpy** (one `scrape_jobs` call for all JobSpy sites, as today).
2. **Keyword APIs** (Adzuna, Jooble, Careerjet): one HTTP call per keyword × location. The key is resolved in the worker through `key_store` (user → platform → `.env`). It never goes into Celery args (existing P0 test pattern).
3. **Feeds**: the whole feed is fetched once and cached in Redis (`feed:{key}`, TTL `FEED_CACHE_TTL_SECONDS`, default 3600). A Redis lock stops parallel keyword tasks from refetching it. Feeds are then filtered in-process by keyword tokens (the same matching as the search-profile prefilter) and by `max_age_hours`. They only run when the user's preferences include **remote**, or when a location is "Remote".

### 3.3 Catalog, keys and requests
- **Migration `0006`:** inserts the new `provider_catalog` rows (tier, requires_key, key_scope, tos_risk, rate_limit, description with the sign-up URL and attribution rule, enabled_global) and updates the `naukri` description to "manual import".
- **`SearchRequest.sources`:** changes from `Literal["linkedin","indeed","naukri"]` to `list[str]`, validated against `registry` keys. The default stays `["linkedin","indeed","naukri"]` plus feeds and keyed sources when available. `effective_sources` already drops what can't run.
- **`enable_naukri_auto`:** still accepted but ignored, with a skipped note "Naukri blocks automated search — use manual import or Apify". Flagged as deprecated.
- **`provider_catalog.sources_seen`:** maps display names to keys through `registry` instead of the hard-coded tuple.

### 3.4 Health: auto-pause (gap noted in P2)
- `availability()` skips a source when `consecutive_failures >= SOURCE_BREAKER_FAILURES` (default 5) and `last_error_at` is newer than `SOURCE_BREAKER_COOLDOWN_SECONDS` (default 1800). The reason shown is "paused after repeated errors, retrying at HH:MM".
- Adapters raise `SourceError`, and `_scrape` calls `mark_failure(key, msg)` per source. One source failing never fails the run.
- Admin `/admin/providers` shows the state already. Reset happens on the next success.

### 3.5 Politeness and quotas
- `rate_limit` from the catalog is enforced per source with a Redis token counter: per-minute pacing, plus a daily cap per key owner (Adzuna's free quota is about 1k calls/month, so roughly 30/day per key by default; configurable).
- Keyword APIs: `results_wanted` maps to page size, with a maximum of 2 pages per keyword.
- When the quota is hit: skip the source with a reason. This is not a failure and doesn't count toward the breaker.

### 3.6 Dedup preference (needs owner decision, see §6)
Today the rule is LinkedIn first, otherwise the longer description. Proposed rule: **LinkedIn > direct company/ATS copy > board (Indeed/Glassdoor) > aggregator/feed**, using the description length only within the same rank. This matters because aggregator URLs are tracking redirects and their descriptions are snippets. It touches `job_dedupe.preferred` and `job_store.upsert_copy`'s conditional UPDATE: a rank column on `jobs.best_source_rank`, added in migration 0006.

### 3.7 Scoring on snippets
Adzuna, Jooble and Careerjet return about 300–500 character snippets. These jobs get `description_partial = true`, and the LLM prompt says "description is partial; don't penalise missing details". We never fetch the full page (that would be scraping the aggregator). The canonical job upgrades automatically when a fuller copy (e.g. LinkedIn) arrives.

### 3.8 Company ATS additions
`company_ats_sources.py` gains `fetch_ashby`, `fetch_recruitee`, `fetch_workable` (POST v3), `fetch_personio` (XML) and `fetch_breezy`. They are also added to `detect_platform` and to `CompanyAtsTarget.platform`. The same SSRF guard and timeouts apply. The slug is validated with a regex (`[A-Za-z0-9._-]{1,100}`), and URLs are built only from fixed hostnames.

6. Add the source breaker (auto-pause), the per-source rate and quota limiter, and per-source failure marking in `_scrape`.
7. Add the dedup rank rule (if approved) and the `description_partial` scoring hint.
8. Add the 5 company-ATS fetchers to `detect_platform` and the schema.
9. Tests:
   - Recorded fixture per source (`tests/fixtures/sources/*.json|xml`).
   - Adapter normalization.
   - Key-missing → skipped.
   - Breaker pause and resume.
   - Feed fetched once under parallel tasks.
   - Adzuna+LinkedIn dedup keeps LinkedIn.
   - Aggregator vs ATS rank.
   - Free-only mode still allows `free_key`.
   - No keys in Celery args.
   - Plus an opt-in `scripts/smoke_sources.py` for live checks (not in CI).
10. Update `CLAUDE.md`: a §6.7 status block, the §7.4 catalog table, and the new env keys.

**New env (all optional):**
- `FEED_CACHE_TTL_SECONDS` (3600)
- `SOURCE_BREAKER_FAILURES` (5)
- `SOURCE_BREAKER_COOLDOWN_SECONDS` (1800)
- `SOURCE_HTTP_TIMEOUT_SECONDS` (20)
- `ADZUNA_API_KEY`, `JOOBLE_API_KEY` and `CAREERJET_AFFID` as `.env` fallbacks, following the existing key_store pattern.

**New dependencies:** none. Use `requests` (already used by the ATS fetchers) and stdlib `xml.etree` for RSS/XML (or `defusedxml` if we want XML-bomb safety; recommended, tiny).

## 5. Risks

| Risk | Mitigation |
|---|---|
| JobSpy sites (LinkedIn, Indeed, Glassdoor) are scraping, so they can rate-limit or break | Existing pacing and retries, the new breaker, high ToS risk shown in the UI, and the keyed APIs as backup |
| Feed ToS (RemoteOK link-back, Remotive no resale) | Keep `source` and the original URL, show "via X" with a link (F3), poll no faster than the TTL, never re-publish feeds |
| Free key quotas run out | Per-owner daily cap, user's own key first, skip with reason |
| Snippet-only jobs score lower | `description_partial` hint, and the canonical copy upgrades when a full copy arrives |
| More sources means slower runs | Feeds are cached; keyword APIs run in parallel threads per task, capped at `SOURCE_MAX_PARALLEL` (4) |
